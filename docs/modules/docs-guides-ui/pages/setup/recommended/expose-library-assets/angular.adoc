[#angular-expose-library-assets]
= Expose Library Assets in Angular Applications

This page covers exposing the static assets of the OneCX libraries an Angular application depends on. See xref:documentation:docs-guides-ui:setup/recommended/expose-library-assets.adoc[Expose Library Assets] for why this matters.

If the application uses OneCX libraries, confirm their assets (e.g. i18n files) are exposed and available in the build output — otherwise assets shipped by those libraries are missing. Nx workspaces commonly configure the assets array in the application's `project.json`; Angular CLI workspaces configure the same assets array under the project's build target in `angular.json`.

.Nx project.json assets configuration
[source,json]
----
...
  "build": {
    ...
    "assets": [
      ...
      // @onecx/portal-integration-angular
      {
        "glob": "**/*",
        "input": "node_modules/@onecx/portal-integration-angular/assets/",
        "output": "/onecx-portal-lib/assets/"
      },
      // @onecx/angular-accelerator
      {
        "glob": "**/*",
        "input": "./node_modules/@onecx/angular-accelerator/assets/",
        "output": "/onecx-angular-accelerator/assets/"
      },
      // @onecx/angular-utils
      {
        "glob": "**/*",
        "input": "./node_modules/@onecx/angular-utils/assets/",
        "output": "/onecx-angular-utils/assets/"
      },
      ...
    ],
    ...
  }
...
----

.Angular CLI angular.json assets configuration
[source,json]
----
...
  "projects": {
    "<project-name>": {
      ...
      "architect": {
        "build": {
          "options": {
            ...
            "assets": [
              ...
              // @onecx/portal-integration-angular
              {
                "glob": "**/*",
                "input": "node_modules/@onecx/portal-integration-angular/assets/",
                "output": "/onecx-portal-lib/assets/"
              },
              // @onecx/angular-accelerator
              {
                "glob": "**/*",
                "input": "./node_modules/@onecx/angular-accelerator/assets/",
                "output": "/onecx-angular-accelerator/assets/"
              },
              // @onecx/angular-utils
              {
                "glob": "**/*",
                "input": "./node_modules/@onecx/angular-utils/assets/",
                "output": "/onecx-angular-utils/assets/"
              },
              ...
            ]
          }
        }
      }
    }
  }
...
----

[#angular-webpack-import-meta]
== Webpack Configuration for importMeta

OneCX libraries (e.g. `@onecx/angular-accelerator`, `@onecx/angular-utils`) and the application itself resolve their translation files with `provideTranslationPathFromMeta(import.meta.url, ...)` from `@onecx/angular-utils`, relative to the URL the code was loaded from. For this to work, webpack must leave `import.meta.url` to the browser instead of replacing it with the local file path at build time. Otherwise translations are missing and the following error is logged:

----
Cannot construct translation path from local file path. Please check whether the webpack configuration for importMeta is correct: https://webpack.js.org/configuration/module/#moduleparserjavascriptimportmeta
----

Disable the `importMeta` parser option in `module.exports` of the application's `webpack.config.js`:

.webpack.config.js
[source,javascript]
----
module.exports = {
  ...config,
  module: { parser: { javascript: { importMeta: false } } },
  ...
}
----

See xref:documentation:docs-guides-ui:concepts/translations.adoc[Translations] for how an application provides its own translation path.
